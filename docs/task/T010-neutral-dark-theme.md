## 2. 背景与目标

现有暗色主题的页面、容器、边框和文字均使用约 220° 色相的蓝紫灰，并叠加蓝绿背景光晕和较大面积的蓝紫选中态，整体更接近品牌化夜间主题，而非 VS Code、Codex 等专业工具常见的中性炭灰深色模式。

本任务将主题调整为“中性炭灰背景 + 经典蓝色交互 + 克制的业务分类色”，通过亮度建立层级，只在按钮、链接、焦点和选中状态使用蓝色。改造不改变页面信息架构和业务行为。

## 3. 已确认设计决策

- 采用中性炭灰体系，不做任何产品的逐像素复刻。
- 应用框架背景完全去紫；紫色仅保留给波形、轨道、情绪标签等数据编码。
- 移除全局蓝绿径向光晕，首页头图区块改为纯色中性容器。
- 常规卡片取消大面积常驻阴影，以边框和表面亮度区分层级；浮层继续保留阴影。
- 全局大圆角由 12px 收敛为 8px，小圆角由 8px 收敛为 6px。
- 启用 Ant Design CSS Variable；应用色板集中在 `theme.ts`，自定义 CSS 仅消费语义变量。
- 本任务只优化现有暗色主题，不增加浅色主题或主题切换。

## 5. 实现范围

### 5.1 Token 与变量治理

- 在 `theme.ts` 建立唯一的暗色色板常量。
- Ant Design token、组件 token 和应用 CSS 自定义属性均由该色板生成。
- 在应用启动时把业务语义变量挂到文档根节点，保证普通页面和 Portal 浮层均可访问。
- 启用具名 Ant Design CSS Variable，避免组件内部继续输出散落的主题色常量。

### 5.2 应用框架

- 页面、侧栏、菜单、卡片、边框和文字切换为中性灰阶。
- 侧栏增加弱边框，导航选中态使用经典蓝色弱背景。
- 品牌图标取消蓝绿渐变，改为纯色主色。
- 滚动条使用中性灰，不再使用蓝紫灰。

### 5.3 页面样式

- 首页 Hero 改为中性次级表面。
- 首页模块卡片、统计卡片及最近产物列表保持清晰的 hover/focus 状态。
- 冥想、TTS、BGM、混音页的常规卡片取消大阴影。
- 冥想时间轴中的语音段使用主题蓝，暂停段使用中性灰。
- 紫色继续用于波形、BGM 轨道和情绪标记，但降低其对应用框架的影响。
- 替换与旧蓝紫色板耦合的硬编码颜色和透明色。

### 5.4 可访问性与一致性

- 普通文字和关键交互文字以 WCAG AA `4.5:1` 对比度为目标。
- 实心主按钮白字与背景对比度不低于 `4.5:1`。
- 验证 hover、active、focus-visible、disabled、错误、警告和成功状态。

## 6. 不实现

- 浅色主题。
- 跟随操作系统切换主题。
- 用户自定义主题或主题选择器。
- 页面布局、组件结构、文案和业务流程调整。
- Codex 或 VS Code 的一比一复刻。

## 7. 验收标准

- 页面、侧栏、卡片和边框在视觉上呈中性灰，不出现大面积蓝紫底色。
- 全局背景与首页 Hero 不再使用蓝绿装饰光晕。
- 蓝色仅承担主要操作、链接、焦点和选中状态；紫色仅承担数据编码。
- `theme.ts` 是色值唯一事实源；业务样式文件不再重复定义主题十六进制色值。
- 首页、冥想、TTS、BGM、混音、产物库和设置页无明显层级、文字或控件可读性回归。
- 前端类型检查、构建、单元测试和 lint 通过。

## 8. 验证方式

- 静态扫描残留硬编码颜色及旧色板值。
- 执行 `npm run build`、`npm test`、`npm run lint`。
- 启动本地前端，通过桌面宽度浏览首页及各主要路由，检查实际计算样式与截图。
