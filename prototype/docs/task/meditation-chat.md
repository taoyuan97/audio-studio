# 冥想剧本生成 · 输入区对话化（Agent 形态）改造任务文档

版本：V1.0
创建日期：2026-08-25
依据文档：`prototype/docs/prd/prd.md`（PRD V2.2）、`prototype/docs/task/tasks.md`（初始任务文档 V1.0）
关联页面：`prototype/meditation-script.html`（初始实现见 tasks.md T4）

---

## 1. 背景与目标

冥想剧本生成页现为「表单式输入」（主题关键词输入框 + 主题快捷 chips + 时长单选 + 生成按钮）。
本次改造将输入区升级为**主流 Agent 对话框形态**：自然语言对话交互，只保留分钟参数设置、大模型切换、输入框、发送按钮。

**生成结果区域（右栏）保持不变**：进度动画、参数摘要、时间轴、脚本预览/编辑、存入产物库、送 TTS 全部沿用现状。

## 2. 已确认决策记录

| # | 决策点 | 结论 |
|---|--------|------|
| C1 | 大模型切换位置 | **composer 工具栏**：输入框下方左下角下拉（主流 Agent 位置，如 ChatGPT 模型选择器），与分钟参数并排 |
| C2 | 分钟参数来源 | **控件为唯一来源**：只认工具栏上的 5/15/30 分钟控件，不从自然语言解析时长，避免理解歧义 |
| C3 | 对话轮次 | **单轮触发式**：每次发送 = 新一次生成，历史消息仅作展示记录，不做追问微调（结果区已有编辑能力兜底） |
| C4 | 任务文档组织 | 新建本专项文档，不改动 `tasks.md` |
| C5 | 模型切换语义 | 仅前端示意：影响气泡模型徽标与产物 `params.model` 记录，**不模拟**不同模型间的生成差异 |

## 3. 交互方案

### 3.1 布局（保持左右两栏 grid-2）

```
┌─────────────────────────┬─────────────────────────┐
│ 对话卡（左栏，改造）      │ 生成结果卡（右栏，不动）  │
│ ┌─────────────────────┐ │                         │
│ │ 消息流（内部滚动）    │ │  进度动画 / 空态 /      │
│ │  空态：欢迎语        │ │  参数摘要 + 时间轴 +    │
│ │       + 建议提示词   │ │  脚本预览/编辑 +        │
│ │  user 气泡（右对齐） │ │  入库 / 送 TTS          │
│ │  assistant 气泡     │ │  （与现状完全一致）      │
│ │   · 生成中：当前步骤 │ │                         │
│ │   · 完成：模型徽标   │ │                         │
│ │     + 摘要 + 引导语  │ │                         │
│ ├─────────────────────┤ │                         │
│ │ composer（底部固定） │ │                         │
│ │  工具栏：分钟 segmented│                         │
│ │         + 模型下拉   │ │                         │
│ │  输入框 + 发送按钮    │ │                         │
│ └─────────────────────┘ │                         │
└─────────────────────────┴─────────────────────────┘
```

### 3.2 对话流细节

- **空态**：欢迎语（说明能力：生成带 `[停顿] [情绪] [呼吸] [语速]` 标记的结构化引导脚本）+ 建议提示词列表
  - 由原 `Mock.MEDITATION_TOPICS` 转化为自然语言建议（如「生成一段深海放松的引导脚本」「我睡前容易焦虑，帮我做一段助眠冥想」）
  - 点击建议词 → 填入输入框（不直接发送，用户可改）
- **user 气泡**：右对齐，显示用户原文
- **assistant 气泡**（左对齐，带模型徽标）：
  - 生成中：显示当前执行步骤文案（与右栏 `GEN_STEPS` 进度同步），如「正在生成：大模型生成结构化脚本…」
  - 完成：参数摘要 + 引导语，如「已用 通义千问 生成「深海放松」5 分钟脚本，正文 386 字，含停顿口播约 6:20。可在右侧查看、编辑，或直接送去 TTS 合成。」
  - **不重复渲染脚本文本**（右栏是唯一结果展示区，避免双份维护）
- **历史消息**：可滚动回看；每次发送触发新一次生成并重置右栏结果（savedId/dirty 同步重置，与现状一致）

### 3.3 composer 结构

- 工具栏（输入框下方一行）：
  - 分钟参数：segmented 5/15/30（复用现有交互与样式，紧凑变体）
  - 大模型下拉：`LLM_MODELS` 两项（DeepSeek / 通义千问，PRD 依据）
- 输入框：textarea 自适应高度（1~4 行），placeholder 示例「描述你想要的冥想主题，如：帮我生成一段缓解睡前焦虑的引导脚本」
- 发送按钮：Enter 发送 / Shift+Enter 换行；空输入禁用；生成中禁用（loading 态）

### 3.4 Mock 逻辑（全部复用，零新增生成逻辑）

- 主题解析：复用 `matchTopic`（`includes` 关键词匹配，长句可命中，如「帮我生成一段深海放松的脚本」命中「深海放松」；未命中走默认模板 + 首句主题词替换）
- 生成：复用 `generateMeditation({ topic, duration })`
- 进度：复用 `GEN_STEPS` + `Mock.fakeTask`，右栏进度动画不变

### 3.5 状态设计（meditation.js）

| 字段 | 变化 |
|------|------|
| `topic` | **移除**（主题随每条消息解析，存于 `messages[i].meta`） |
| `messages` | **新增**：`[{ role: 'user' \| 'assistant', text, meta?: { model, topic, duration, wordCount, totalTime } }]` |
| `model` | **新增**：`'deepseek' \| 'qwen'`，默认 `'deepseek'` |
| `input` | **新增**：输入框受控文本 |
| `duration` / `generating` / `stepDone` / `progress` / `result` / `editing` / `draft` / `savedId` / `dirty` | 保留，语义不变 |

### 3.6 产物入库

- `params` 新增 `model` 字段（记录生成所用模型，示意）；其余（topic / matchedTopic / duration）与现状一致

## 5. 任务分解

### MC1 chat 组件样式（main.css）

**内容**
- `.chat-card`：flex 纵向布局，占满 grid-2 行高；消息流区 `flex:1; min-height:0; overflow-y:auto`
- `.msg-user` / `.msg-ai` 气泡（右/左对齐，模型徽标）
- `.suggest-chips`：空态建议提示词（自然语言短句样式，区别于原主题 chips）
- `.chat-composer`：工具栏（分钟 segmented 紧凑变体 + 模型下拉）+ textarea 自适应（1~4 行）+ 发送按钮
- 暗色主题变量对齐（复用现有 CSS 变量）

**验收标准**
- 静态结构渲染正常，与现有暗色风格一致，无控制台报错

### MC2 Mock 层（mock.js）

**内容**
- `LLM_MODELS` 常量 + 导出

**验收标准**
- 控制台可访问 `Mock.LLM_MODELS`

### MC3 页面重构（meditation.js + meditation-script.html）

**内容**
- state 改造（见 3.5）
- 左栏对话渲染：空态（欢迎语 + 建议词）、消息流、composer
- 发送交互：Enter/按钮发送、空输入禁发、生成中禁发、建议词点击填入
- 主题解析接 `matchTopic`（以整条消息文本为输入）；生成链路复用 `GEN_STEPS` + `generateMeditation`，右栏进度/结果联动与现状一致
- assistant 气泡：生成中显示当前步骤 → 完成显示模型徽标 + 摘要 + 引导语
- `doSave` params 增加 `model`；page-desc 文案更新

**验收标准**
- 见第 6 节总验收清单

### MC4 联调验收

**内容**
- 本页全流程走查 + 对其余页面零影响的回归确认（重点：TTS 页接收 handoff 预选、产物库展示新产物）

## 6. 验收标准（总清单）

- [ ] 空态显示欢迎语 + 建议提示词，点击填入输入框，可修改后发送
- [ ] 自然语言长句正确命中主题（如「帮我生成一段深海放松的引导脚本」→ 深海放松模板）；未命中主题走默认模板且首句主题词替换正确
- [ ] 分钟 segmented、模型下拉位于 composer 工具栏，切换即时生效并体现在下次生成（气泡徽标 + 产物 params）
- [ ] Enter 发送 / Shift+Enter 换行；空输入禁发；生成中发送按钮禁用
- [ ] 生成中：右栏结果卡进度动画与现状一致，assistant 气泡同步显示当前步骤
- [ ] 完成后：右栏结果展示、时间轴解析、编辑保存、重新生成重置逻辑均与现状一致
- [ ] assistant 完成气泡含：模型徽标、主题/时长/字数摘要、引导语；不重复渲染脚本文本
- [ ] 多次发送形成可滚动回看的历史；每次发送触发新一次生成并重置右栏（含 savedId/dirty）
- [ ] 入库产物 `params` 含 `model` / `topic` / `matchedTopic` / `duration`；送 TTS 后 handoff 预选正常
- [ ] 全程无控制台报错、无网络请求；其余页面零影响

---

## 7. 明确不做（Out of Scope）

- 不从自然语言解析时长（C2：控件为唯一来源）
- 不做追问微调 / 多轮改写（C3：单轮触发式）
- 不模拟不同模型间的生成差异（C5：仅徽标与 params 记录）
- 播客页等其他模块输入区不改动（如需对话化另立任务）
